## 成功标准

新人能从运行模板开始，沿着同一个案例完成操作、修改和验证，并理解下一步为何需要一个新概念。有经验的开发者能独立完成具体任务。正在使用模板的人能直接查到当前 API、配置、命令与错误处理。

重构完成同时满足：

- 每个公开页面有明确读者、目标与内容类型；一个页面负责一种主要任务。
- 贯穿教程有可保存的前章成果、准确前提、最小示例、可观察结果和修改练习。
- 操作指南能独立进入；概念页解释关系与取舍；参考页提供可查的事实。
- 中文和英文内容、链接、章节身份与导航对应，补齐版本缓存章的英文。
- 已发布的中文路径和 `/en/` 镜像继续有效；移动 Markdown 源文件不隐式改变发布地址。
- API 与配置来自当前实现；教程和参考中的命令在该源码版本存在。
- 移除知识库示例后，相关教学资源同步移除，Core 文档与站点仍可构建。
- 本地构建、链接校验、真实站点浏览器旅程和 Standards + Spec review 有可追溯的证据。

维护者资料从作者与贡献入口进入，不塞进初学者的主阅读顺序。站点保留既有首页、文档、博客、下载四类顶层入口。

## 贯穿案例：团队知识手册

初始状态是一份可运行的完整模板。学习者逐步完成真实操作，并在指定位置修改最小代码、验证行为；源码讲解建立在当章已观察到的结果之上。

账号 A 是企业 Owner，账号 B 是普通 Member。教程明确区分企业角色和知识库的 Reader / Editor 授权。第三章先在 B 的个人库写作；共享章由 A 新建“团队手册”共享库，并用前章正文新建“入职指南”，对应当前已有的能力。

| 章节                | 保留的成果                   | 新增概念                      | 完成检查                                 |
| ------------------- | ---------------------------- | ----------------------------- | ---------------------------------------- |
| 1. 第一条全栈请求   | 开发栈与服务状态             | HTTP、生成合同、SDK、持久事实 | ready 为 200，故障与恢复可解释           |
| 2. 账号和会话       | A / B 两个开发账号           | User、Membership、Session     | 刷新保留身份，退出撤销当前会话           |
| 3. 第一篇入职指南   | B 的个人库文档与 URL         | 业务用例、事务、幂等          | 保存、刷新、列表重开得到相同内容         |
| 4. 编辑、搜索与冲突 | 修改后的正文和两个标签页     | 预览、查询、版本与草稿        | 旧版本保存失败且输入仍在                 |
| 5. 与同事共享       | 共享库内的入职指南、B 的授权 | 资源权限与继承                | Reader 可读不可写，Editor 可写，撤权拒绝 |
| 6. 附加入职资料     | ready 附件与正文引用         | 候选对象、核验与发布          | 下载内容一致，新的无权请求被拒绝         |
| 7. 导出与通知       | 一次导出、ZIP 和通知         | 快照、入队、Worker 与终态     | ZIP 内容正确，刷新后可查同一结果         |
| 8. 失败与追溯       | 任务尝试与关联检查记录       | 重试预算、审计、request_id    | 失败可定位，重试历史保留                 |
| 9. 扩展自己的业务   | 新业务贡献和所有权登记       | 显式组装点、Core 边界         | 路由、双语消息与生成合同检查通过         |
| 10. 部署与保护数据  | 部署配置与恢复证据           | 维护窗口、备份、独立恢复      | 在隔离环境读取恢复的数据                 |

第 9、10 章是从课程进入独立指南的桥梁。接入新业务使用已有的便签示例和公开贡献合同；生产部署与恢复在专用环境完成，不要求新人改动正在使用的数据。

每章至少有一个“改变一个条件”的练习，说明编辑哪个文件或输入、替换哪段内容、运行什么命令和预期结果。代码示例从公开 SDK、公开模块接口或受检查的源码片段获取，入门章只展示当前概念需要的部分。

## 写作与维护规则

规范落在一个作者指南中，引用本次理念与 CONTEXT。AGENTS 只增加按“修改公开文档”触发的短入口，导向该指南；保留用户现有修改和导入技能。

| 页面类型 | 结构                                                                       | 验收问题                               |
| -------- | -------------------------------------------------------------------------- | -------------------------------------- |
| 教程     | 目标与前提 → 最小操作或代码 → 观察 → 心智模型 → 改一个条件 → 验证 → 下一章 | 能沿用上一章成果完成并解释本章吗？     |
| 任务指南 | 要完成的任务 → 前提 → 步骤 → 成功检查 → 失败恢复 → 相关概念                | 从此页进入也能完成任务吗？             |
| 概念     | 一句话定义 → 关系图 → 最小例子 → 关键取舍 → 实践链接                       | 能知道何时使用、为何存在和适用边界吗？ |
| 参考     | 范围与来源 → 分类索引 → 字段 / 接口 / 状态 → 限制 → 关联指南               | 能快速定位准确值与调用合同吗？         |

使用当前时态描述当前能力；过去的票号和验收记录放在维护者资料。明确标记默认值、示例值、占位参数与源码版本。命令写清执行目录、是否启动依赖、是否修改数据与停止方式。

截图只用于帮助辨认实际界面或结果，使用可复现的开发数据并记录对应版本；界面变更时更新相关截图。架构关系用简洁图示，避免用截图代替接口、代码和文本。中英文共享操作语义，代码标识符、配置键与 operationId 保持原文。

参数和限制尽量链接生成参考；教程只重复完成当前步骤所需的信息。更新一项能力时同步调整相关教程、指南、参考、代码示例、双语页与示例所有权。已废弃的内容说明适用版本和替代入口；移除公开路由需要明确迁移安排。

## 参考与文档工程

### 参考内容

API 参考从 OpenAPI 读取 tags、路径、方法、operationId、参数、请求体和响应 schema，保留 JSON 下载。字段引用和组合 schema 按合同呈现；认证要求只写合同已声明或实现已核对的内容。示例请求使用当前实现能接受的形状。

服务端配置继续从 Rust 字段定义生成。开发脚本、浏览器设置和文档发布变量单独说明，标明各自来源；敏感值只显示名称和配置要求。

命令参考按开发、生成、验证、桌面、性能和部署分类，并与实际 task runner 核对。错误参考提供 HTTP 状态、稳定码、用户可采取的行动以及 request_id 的定位方式；具体错误码与已登记来源核对。

### 自动校验

继续使用既有 `pnpm docs:check`、`pnpm docs:build` 和 `just e2e-docs`，在这些入口补齐文档合同：

- 校验内容类型、双语声明、稳定 id、来源文件、导航和课程前后章关系。
- 检查发布页面、页内锚点、跨语言链接、子路径部署与源码链接。
- 解析 Markdown 的结构验证代码围栏、片段和链接，避免把代码中的示例链接当正文链接处理。
- 校验被登记的命令与 task runner，以及生成 API / 配置的事实来源。
- 对具有真实教学价值的可执行示例，使用现有公开行为测试或编译检查；给测试标明运行环境与边界。
- 在临时工作副本执行删例并构建站点，验证新教程和相关导航的所有权。

人工审阅负责概念增量、练习质量、说明是否足够、是否重复，以及截图与实际应用是否一致。模板字段通过只证明结构成立，课程仍需实际跟做。

交付：双语文档首页、任务与概念索引、README 阅读入口、作者规范、明确的页面类型和课程关系。现有内容先用新分类进入，随后逐页改写。

### DOC02：完整团队手册课程

交付：全部双语连续章节、最小可运行代码与操作、前章成果、观察结果、修改练习和前后章导航。教程中示例专有的内容登记知识库所有权；Core 章节可独立保留。

验收：从干净模板按顺序完成课程，得到文档、共享授权、附件、导出、通知与验证记录；每个练习有执行位置和成功条件；示例移除后无悬空课程链接。

验证：课程引用的 SDK / HTTP / View 合同与定向测试、一次真实浏览器关键旅程、删例后的文档构建。依赖 DOC01。
