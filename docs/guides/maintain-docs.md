# 维护开发者文档

文档随公开能力一起交付：实现自己的 SaaS 功能时，同时更新使用该接口的教程、代码示例、双语说明和验证入口。

## 选择正确的页面

| 类型     | 开始写什么                             | 完成检查                       |
| -------- | -------------------------------------- | ------------------------------ |
| 教程     | 前章代码状态、本章新增变更与结果       | 同一份业务代码可以继续下一章   |
| 任务指南 | 当前开发目标、前提、公开接口与最小实现 | 独立进入也能完成任务           |
| 概念     | 定义、真实关系图和最小代码             | 能理解何时使用、为何存在和边界 |
| 参考     | 事实来源、分类、参数、返回与限制       | 能定位当前准确合同             |

后端教程以文件、代码、请求和结果为主。每步明确执行目录、依赖、完整变更和预期响应；复杂实现先给最小可运行路径，再解释关键细节。

## 登记双语页面

Markdown 是唯一可编辑正文来源。在中文文件旁创建同名 `.en.md`，在 [site.json](../site.json) 登记稳定 id、两组标题、源文件、发布路由、分组和页面 type。

教程序列使用 `previous` / `next` 的章节 id。没有明确关系时关闭自动相邻页，避免把下一章送到不相关的指南。

旧发布路径保持稳定；源文件可以移动，链接和站点声明一起更新。生成站点根据当前语言解析目标，页脚链接到构建使用的提交。

## 让代码保持可运行

使用 `<<<` 引用受检查的源码。示例应明确插入位置，并在同一验证入口编译或执行；片段链接到完整实现。API DTO 来自 Rust/OpenAPI，配置默认值来自 Settings/FIELDS。

```bash
pnpm docs:check
pnpm docs:build
```

对应业务的 HTTP 或公开能力检查验证成功、拒绝和关键失败。浏览器验证阅读与导航；这些证据各有责任，构建成功不能代替教学跟做。

## 示例内容的所有权

专有教程与代码登记在示例清单；共享页面中的示例链接放入已登记 marker。移除参考业务时，相关内容和导航一起移除，Core 文档仍应可构建。
