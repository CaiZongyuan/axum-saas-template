# Rust Public Integration Map

This page is for backend developers implementing their own business modules. Look up HTTP DTOs in the [API reference](site:reference/api.md); linked source defines the complete Rust signatures and limits. Complete [Add a backend module](../guides/develop-module.md), then select the capabilities you need.

`saas_app` exposes SaaS Core and HTTP boundaries. `saas_platform` exposes configuration and infrastructure adapters. Business modules call these public interfaces; API and Worker compose them explicitly at the application layer. The current organization model is a single Organization. Storing multiple customers in one database does not automatically provide tenant isolation.

| [`background_credential`](../../crates/app/src/modules/identity/mod.rs), [`credential_is_current`](../../crates/app/src/modules/identity/mod.rs) | Authorized actor's request transaction / Worker publication transaction                | `Option<CredentialRef>` / `bool`, database errors  | Persist credential references instead of Cookies; Worker checks never extend original credential lifetime                              | [Credential behavior tests](../../crates/app/tests/sessions.rs)                                                   |

`require_session` returns identity. Your ticket or billing rules remain responsible for current resource access. Check those rules in the same use case as the mutation to avoid a check followed by a write in a separate transaction.

## Caller-Owned Database Transactions

These entries accept `&mut PgConnection`. Pass the same `&mut *tx`, check every result and commit once from the business use case. Business data, audit and jobs belong in that shared transaction.

| Public entry                                                                                                                                                                                | Input / output                                                                  | Errors                                               | Transaction responsibility                                                                                                            | Checked usage                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| [`enroll`](../../crates/app/src/modules/organization/mod.rs)                                                                                                                                | New user id → `MemberRole`                                                      | `sqlx::Error`                                        | Enroll in the current organization within account creation; the organization row serializes first-Owner initialization                | [Registration transaction tests](../../crates/app/tests/registration.rs)                                                |
| [`active_role_in`](../../crates/app/src/modules/organization/mod.rs), [`lock_memberships`](../../crates/app/src/modules/organization/mod.rs)                                                | User id / id list → current role / membership records                           | `sqlx::Error`; membership may be missing or inactive | Lock members before resources; lock multiple members in id order, matching administration                                             | [Membership concurrency tests](../../crates/app/tests/membership_policy.rs), [Member guide](../tutorials/08-members.md) |
| [`append`](../../crates/app/src/modules/audit/mod.rs) / `Event`                                                                                                                             | Actor, action, resource and `Source` → `()`                                     | `sqlx::Error`                                        | Share the business transaction; audit failure rolls business data back; metadata excludes arbitrary request JSON and secrets          | [Audit HTTP tests](../../crates/app/tests/audit.rs), Audit integration                                                  |
| [`fingerprint`](../../crates/app/src/modules/idempotency/mod.rs), [`claim`](../../crates/app/src/modules/idempotency/mod.rs), [`complete`](../../crates/app/src/modules/idempotency/mod.rs) | `Attempt`: actor, scope, key and payload hash → previous response / `()`        | `InvalidKey`, `Conflict`, `Unavailable`              | Authorize before claim; replay existing responses; complete new results before commit; failures leave no business data or reservation | [Ticket idempotency](../../examples/tutorial-tickets/application.rs)                                                    |
| [`enqueue`](../../crates/app/src/modules/jobs/mod.rs) / `NewJob`                                                                                                                            | Kind, schema_version, business payload, attempt budget and correlation → Job id | `sqlx::Error`                                        | Enqueue with the business snapshot; kind needs a registered Worker Handler; payload excludes tokens and signed URLs                   | [Public job tests](../../crates/app/tests/jobs.rs), Job guide                                                           |
| [`on_job_outcome`](../../crates/app/src/modules/notifications/mod.rs) / `JobNotification`                                                                                                   | Job id, recipient, stable event_key, generic subject and target → `()`          | `sqlx::Error`                                        | Register intent with enqueue; Jobs publishes inside its terminal transaction; targets check current access                            | [Notification HTTP tests](../../crates/app/tests/notifications.rs), Notification guide                                  |
