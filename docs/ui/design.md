## 4. 架构方案

### 4.1 优先设计：零个、一个、多个 example 的 UI 组合

用户进一步明确：这是 template，example 的解耦性优先于知识库页面的具体布局。因此，知识库导航与「我的文档」默认入口只能属于当前示例组合，不能成为通用应用壳的内部假设。

Q10/Q11 已确认：支持零个、一个或多个示例共存，开发者在源码装配阶段增减，重新构建应用。该架构取舍记录在 [ADR 0003](../adr/0003-static-example-composition.md)。该契约已随 UI02 落地：壳与 Core 不 import 具体示例，示例经 `apps/web/src/app-examples.tsx` 的显式组装点接入页面、导航分组、双语文案、可选默认入口、通知解析与场景；`scripts/example-remove.mjs --example <id>` 按各示例的 manifest 与 `example:<前缀>:*` 标记整建制移除。零、单、双示例四种源码组合由 CI 的 example-removal 任务真实构建验证；默认入口由组装裁决（第一个声明者胜出，组装处可显式覆盖）。

| 装配结果         | 导航与页面                                                                                 | 首页和设置                                                               | 翻译、教程与展厅                                                  |
| ---------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 零个示例         | 仅保留登录、企业成员、通知、任务、审计、API Keys、系统状态等 Core 能力；权限继续决定可见性 | 通用首页可用；外观、语言与设计系统设置完整保留                           | Core 中英资源、教程与基础组件场景保留；不存在知识库专属入口或文案 |
| 只有知识库       | 壳接收知识库注册的「我的文档 / 知识库」入口和页面                                          | 当前模板可以配置默认进入我的文档；通用设置复用同一实现                   | 加入知识库中英资源、教程、文件图标用法和文档交互场景              |
| 知识库与其他示例 | 同一壳内按业务分组展示各自入口；Core 功能只有一份                                          | 增加示例不擅自改变已有默认入口；应用组合可显式选首页，失效时回到通用首页 | 按示例组织资源与场景；显示标签本地化，翻译 key 和路由标识避免冲突 |
| 从多个中移除一个 | 该示例的导航、路由与独占页面代码一起移除，其余分组保持稳定                                 | 如果默认入口属于被移除示例，回到通用首页；不随机跳入另一个业务           | 同步移除其双语文案、教程、场景和独占依赖，保留仍被使用的共享依赖  |

Core 通知或审计中已有的历史记录不随源码移除而删除。目标业务已不在当前构建时，展示通用的「相关功能当前不可用」反馈，不保留指向不存在页面的可点击目标；旧书签同样有可返回首页的不可用页面。此行为不替代 API 授权，也不意味着删除生产业务数据。

Core 首页保留稳定的 `/` 入口；登录/注册完成后才按应用配置选择业务默认入口，合法业务深链接优先于默认入口。直接访问 Core 首页不会被强制送回知识库。默认入口仅在已注册且当前用户可进入时生效，否则回到 Core 首页，避免移除示例后的重定向循环。

#### 一个示例拥有一个前端接入入口

通用壳只消费组装后的导航和页面信息。示例通过自己的入口提供需要的页面、导航、翻译和可选演示场景；应用组装点负责接入，Core 不导入具体示例。接入合同包括稳定 id、路由装配、导航与语言资源，以及可选通知解析和展厅场景；实际 Router 类型只存在于应用适配层，通用壳不依赖平台 Router。

| 归属                 | 持有的内容                                                                       | 增减示例时是否修改                 |
| -------------------- | -------------------------------------------------------------------------------- | ---------------------------------- |
| 通用应用壳与基础组件 | 框架布局、导航渲染、设置框架、主题/语言选择、通用首页、Core 页面                 | 应保持不变                         |
| 示例自身             | 页面、业务导航定义、中英消息、业务状态展示、通知目标解析、示例教程及可选展厅场景 | 增加或移除该示例                   |
| 应用组装点           | 所选示例入口、默认入口策略、业务与 Core 的连接                                   | 显式增加或移除注册                 |
| 所有权与构建工具     | 文件、接入标记、独占依赖、教程与迁移历史的归属                                   | 更新对应示例登记，重生成合同和文档 |

目标是让开发者添加第二个示例时，写该示例自己的代码并在明确组装点注册；不需要逐个修改侧栏、首页、设置、通知页、翻译 provider 和展厅内部的条件分支。UI 的一个接入入口不代表整个后端也只需一行配置：API、Worker、生成合同等仍通过各自显式组装点接入。

接入接口必须满足：

- 每个示例具有稳定 id；路由 id、翻译 namespace、展厅场景 id 和通知目标类型有明确归属。重复 id、冲突路由或冒用 Core 保留路由在构建/检查时失败，不能后注册者静默覆盖。
- 导航显示名来自示例的翻译资源；通用壳不通过中文名或 `if (example === 'knowledge')` 分支识别业务。
- 业务入口可按权限隐藏，但隐藏菜单不是资源授权。所有直接路由、数据请求和服务端 API 继续执行各自授权。
- 空业务分组不显示；已选业务入口不可用时回到明确的 Core 首页。保留既有知识库深链接兼容性，具体路由装配不得靠遍历文件名猜业务。
- 示例可以消费 Core 和通用 UI；示例之间默认不直接 import。真正共享的能力先有独立归属，不能登记为某一示例独占后又被另一个示例使用。
- 示例运行时接入信息与文件所有权清单职责不同：前者供 UI 组装，后者供移除工具与构建检查。通过稳定 id 和检查关联，不把源码路径清单发送给最终用户界面。
- 移除示例要删除该构建的代码与独占依赖，并同步裁剪两种语言的教程与引用。现有仅针对知识库的清理工具需推广为按示例 id 工作，不能仅隐藏菜单就声称解耦完成。

相应工具必须支持按示例 id 选择清单与注册标记，汇总所有示例的边界和保留迁移，拒绝重叠的独占路径或相互冲突的所有权声明。共享依赖与资产独立登记，不因移除某一示例而删除；只有目标示例独占且其他模块不再需要的依赖才随之裁剪。现有 `exampleActive(root)` 等辅助判断也要明确查询哪个示例，不能以 Knowledge 是否存在代表整个应用是否有示例。

#### 通过真实组合验收解耦

验收矩阵至少覆盖 `Core`、`Core + Knowledge`、`Core + 第二测试示例`、`Core + 两个示例`，并分别移除其中一个后重新构建。第二示例采用很小的测试 fixture，至少接入可访问页面、导航、双语消息与一个演示场景，用于证明 UI 组装接口不认识 Knowledge；不因此扩大为另一个完整产品开发任务。现有 Notes 练习只有后端接入，不能替代此 UI 验收。

从公开页面检查：登录与设置可用，导航只出现当前组合的入口，中英文和明暗可切换，展厅只出现已注册场景；重建教程无悬空链接，历史通知与旧书签可解释地回退。静态边界检查同时保证 Core 不反向导入示例、示例不互相导入、删除后没有残留业务引用。

增减以源码装配和重新构建为边界。本轮不提供部署开关或管理员运行时启停；也不将业务分组设计成企业/Workspace 切换器。

### 4.2 包职责与平台接线

| 层               | 职责                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| `apps/web`       | Router、偏好初始化、浏览器能力、通用与示例导航注册、实际 SDK 连接                     |
| `apps/desktop`   | 原生窗口、IPC、系统交互与 Web 加载；共享外观沿用同一套页面                            |
| `packages/views` | 应用外壳、设置、组件展厅、各能力页面；平台行为由显式回调或能力接口注入                |
| `packages/ui`    | 通用 primitives、语义 tokens、交互与无障碍表现                                        |
| `packages/core`  | 平台无关的客户端纯逻辑；不引入 React hooks、localStorage、matchMedia 或知识库内部类型 |
| 知识库示例       | 业务页面、业务翻译、导航和示例场景登记到所有权清单                                    |

通用组件展厅应在移除知识库示例后仍能打开。若展示保存冲突、文档权限等业务组合，应通过可移除的示例注册接入。翻译资源也需要区分 Core 与示例所有权，避免删例后留下悬空引用。

服务端资源继续由现有查询机制管理；导航状态归路由；短期交互状态归组件。是否需要新增状态库或独立 i18n 包，以实际需求与依赖方向决定。

采用以下模块接口与职责：

- 共享 `AppShell` 接收导航项、当前页面信息、用户区域和内容插槽；菜单业务来源由应用入口注册，不在 shell 内硬编码知识库对象。
- 共享设置页通过回调读取/修改当前设备偏好；浏览器存储、媒体查询和 Desktop IPC 由平台适配器实现。
- React 的语言/主题 provider 放在共享 View 层或通用 UI 层的合适位置，不进入禁止 React 的 Core；UI primitives 通过 props 接收可读标签，不反向依赖 View 的字典。
- 中英消息按能力组织，Core 界面与知识库界面分别持有自己的资源；知识库的通知显示解析器、导航项和展厅场景由组装点注册。
- 组件展厅按需加载；使用独立的演示状态和 fixtures，不复用当前用户的业务数据。资源查询仍只有现有 Query 缓存一份事实源。
- 本次不需要引入 Next.js、第二套 renderer 或仅为偏好建立全局状态库。继续使用 Vite、TanStack Router/Query 与 Base UI。

## 5. 视觉与交互

先以无示例的通用壳、设置和基础展厅建立视觉基线，再接入知识库代表页面与第二测试示例验证组合；相同规范覆盖成员、权限、通知、任务、审计和 API Keys。

语义 token 覆盖工作面、导航面、浮层、正文/次要文字、边框、焦点、主要动作、选中、成功、警告和危险。每个 token 同时定义明暗取值，页面使用语义角色。字体优先采用支持中英文的系统字体栈。

当前方案：
