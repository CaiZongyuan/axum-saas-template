# SaaS Template Spec 讨论与决策记录

规范正文：[SaaS Template 架构与实施规范](./saas-template-architecture-spec.md)。本记录用于保留讨论依据和待确认事项，不构成第二套实现规范。

## 讨论方式

用户希望先理解概念和取舍，再共同制定方案。对“不确定”不视为接受推荐。最新澄清明确了：example 是覆盖大多数核心特性的可运行教程，业务流程保持简单、可以仿照实现自己的业务、容易移除，并且功能实现与在线教程同步交付。

已确认的选择立即写回正文和术语表。适合 ADR 的长期决策单独记录；暂定的数值或普通库选型不各自创建 ADR。

## 收敛后的设计树

```text
单机、简单参考应用
 ├─ 每部署一家企业 [已确认]
 │   ├─ 单 Organization、无企业切换 [已记录 ADR]
 │   ├─ 注册页面自助加入 [已确认，替代邀请]
 │   └─ 知识库级授权 [已确认]
 │       ├─ 文档/附件继承 [已确认]
 │       └─ Member 默认可写个人库；其他库按 Grant；Owner/Admin 全部可见 [默认实现]
 ├─ 邮箱密码 [已确认]
 │   ├─ 自助注册后建立会话；找回/可选邮箱验证独立操作 [完整性合同]
 │   └─ Axum Identity、不加 Better Auth 服务 [建议默认]
 └─ 企业知识库 [已确认]
     ├─ 在线 Markdown + 预览 + RustFS 附件 [已确认]
     ├─ 保存即生效、标题搜索、无回收站 [建议默认]
     ├─ 小操作贯通：文档导出、缓存、权限、API Key、通知、审计/trace
     ├─ 能力覆盖矩阵 + 在线教程 + 测试 + 实際删例验收 [已确认交付要求]
     └─ 正文全文检索/独立 broker/Outbox 为后续扩展
```

协议、文件状态机、并发和重试细节已经在正文形成可评审合同；它们不是额外的 example 产品功能。具体 TTL、重试次数、容量和性能预算是可配置实施起点，需在实际实现中验证。

## 原稿问题的处置

首次审阅通读原稿第 0–56 章，发现以下问题。正文现已重新组织为 24 节，下面按问题归纳处置，不再使用旧章号引用当前规范。

| 原问题 | 当前处理 |
| --- | --- |
| Workspace/Tenant/Organization 混用 | 单企业部署；统一 Organization 与 Knowledge Base，删除额外 Workspace 层 |
| 模块隔离与跨模块事务缺少衔接 | 公开 Application API、外层共享事务、表归属与依赖方向合同 |
| 认证、会话、多端凭据描述不完整 | 自助邮箱密码注册、重置、Cookie/CSRF、撤销与 Electron 同源壳建议 |
| 角色/API Key/撤权语义不明确 | 明确企业角色、库 Grant、凭据权限交集和撤销边界 |
| Teamspace 的 Task/Tag 缺少一致交付范围 | 主示例替换为知识库/文档/附件；Tag 不是强制功能 |
| 文件只列 status 没有生命周期 | 上传完成核验、不可覆盖最终对象、权限、幂等、清理与备份合同 |
| Job/Outbox/Inbox 一律串联 | 本地业务与 Job 同事务；真实跨 broker 发布时才引入 Outbox/Inbox |
| RabbitMQ 既 optional 又生产必装 | 移出默认部署及 v1 门槛，保留需求驱动的选型与扩展合同 |
| Entitlement 同时属于 Core 与后续模块 | 商业政策按业务决定，不预置通用计费引擎；平台上限单独处理 |
| 审计/通知与业务提交关系不明确 | 必须审计同事务；邮件异步投递、失败可见、清楚区分重复副作用 |
| API 只有响应形状 | 增加错误语义、游标、幂等 scope、短期凭据重签、版本冲突 |
| 依赖失效/健康/关停模糊 | 增加降级矩阵、租约、有限关停、trace 与敏感字段约束 |
| 默认启动承诺完整示例但缺 Worker/S3 | Default development 包含完整依赖，Minimal 明确仅 smoke |
| 恢复演练与备份指导表述不一 | 基本命令 + 一次独立环境恢复，不设复杂 SLA 数字 |
| 删除/附件/备份关系缺失 | 简单删除、可靠对象清理；备份中的历史数据与未完成上传另有明确规则 |
| 质量集中后置、邀请早于邮件/队列 | 邀请方案已移除；注册不依赖发信，重置/附件清理/导出在自身验收前接入真实 Jobs；在线教程按阶段交付 |

## 一致性核验

对照原稿保留了 monorepo、模块边界、多端共享、真实适配器测试、文档投影与生成引用、7 类性能验证、Desktop soak、单机生产运维、可观测性和可替换 Reference Domain。

只读复核发现并已补齐：

- token hash 与可恢复重置邮件之间的短期加密投递材料；同邮箱重复注册不能改写既有账号、提升角色或恢复停用状态。
- ready 文件不能被仍有效的暂存上传 URL 覆盖；上传幂等不反复返回过期 URL。
- 租约过期也消耗有限尝试预算；手动重试保留历史。
- 备份覆盖数据库引用的不可变 ready 对象，明确未完成上传的恢复规则。
- API Key 一次性 secret 与通用响应重放缓存的边界。

上述问题已进行第二次定向复核，文档层面的合同缺口已关闭。本地相对链接、代码围栏、章节编号和 diff 空白检查通过；仓库尚无对应应用实现，因此没有声称后端、E2E 或性能目标已经实测通过。

## 最新参考仓库研究

按用户提供的两个项目核查了官方源码与文档，见 [参考模板研究](./research/template-reference-patterns.md)。确认可借鉴的是简单示例、完整工程链路与新增业务教程；没有把两仓库未提供的完整删例工具说成既有事实。

基于最新目标，文档导出从后置功能调整为一个小型、可见的任务教学场景；Redis 也指定真实的已授权文档缓存场景。它们复用同一篇文档，承担 Jobs、通知、存储、幂等、缓存和 trace 的教学，而不扩张为复杂业务平台。

## 当前边界

自助注册、Markdown 写作、RustFS、example 的教学定位和同步在线文档均已得到用户明确指示，不再重复请求确认。此前包含邀请注册的整组默认确认已被这些修订替代。

首账号 Owner、个人库自动准备等属于满足直接注册写作的具体默认实现；管理员内容可见范围、数值参数等仍以正文明确的草案合同为准。本文只描述规范修订，不声称 example、移除脚本或在线站点已经实现/发布。其余实施默认随下方已确认的 GitHub 规格与任务推进。
