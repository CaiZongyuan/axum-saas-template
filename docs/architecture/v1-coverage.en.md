# v1 capability coverage and acceptance

This page is v1's ledger: every row of the spec's [§8.6 feature coverage matrix](../saas-template-architecture-spec.md) lands here as real links — run entries, source guides, online tutorials and verification map one to one, and the doc build's existence checks guard every link target (a missing source file fails the build), so tutorials and source never drift apart silently. The matrix records only **delivered** capabilities; design notes (such as spec §15.2's Mobile and the Outbox extension chapter) stay out of the matrix and carry no coverage marks — the documentation leaves no blanks to fill. Evidence for Core capabilities is written directly into the matrix and is guaranteed to hold after [removing the examples](../tutorials/23-example-removal.md).

## Four reading paths

1. **Quick start**: [Quick start](../getting-started/quickstart.md) — toolchain, `just dev`, registering the first account, service status and failure scenarios.
2. **Follow the tutorials**: start from [the first full-stack request](../tutorials/01-full-stack-request.md) and work chapter by chapter; every chapter maps to real commands and tests.
3. **Build your own business**: [compose and remove reference examples](../tutorials/23-example-removal.md) — delete the knowledge-base example per the ownership manifest and Core keeps running as before.
4. **Verification and reference manuals**: [running tests and checks](../testing/t01-feedback-loop.md), [Core and example boundaries](./module-boundaries.md), and the generated references ([API contract](site:reference/api.md), [API configuration](site:reference/config.md)).

## Acceptance summary

- **Default full stack**: tutorials delivered ticket by ticket starting from [the first full-stack request](../tutorials/01-full-stack-request.md); daily gate `just check`, real browser journeys `just e2e`, milestone `just check-full`.
- **Electron**: [the secure shell tutorial](../tutorials/20-electron-shell.md) + desktop smoke (`just desktop-smoke`, every PR in CI).
- **Mobile**: not implemented and not planned for v1 (implementation ticket [#22](https://github.com/CaiZongyuan/axum-saas-template/issues/22) recorded as not planned). Spec §15.2 and the testing strategy's Mobile entries stay as design notes and are not to be implemented from (the implementation decision follows #22; the divergence is intentional); no corresponding checks, no documentation blanks.
- **Performance**: deterministic budgets are accepted every PR with `just check` (`perf-ci`); load/saturation/trajectory soak reports are produced only by [perf-nightly](../../.github/workflows/perf-nightly.yml) (nightly, manual and release triggers), artifacts kept 30 days, never acting as a PR gate.
- **Backup and restore**: [backup and isolated-environment restore drill](../tutorials/22-backup-restore.md) verifies documents, attachments and jobs on an isolated restore environment; the archive carries no secrets, and the drill cleans up credentials and certificates at the end.
- **Example removal**: [removing the examples](../tutorials/23-example-removal.md) executes per the ownership manifest; CI's example-removal job drills the whole thing every PR; after removal `just check-core` is green.
- **Generated references**: the API contract is generated from OpenAPI (`contracts:check` guards drift), the configuration reference is generated from Settings and cross-checked against `.env.example`; the permission and job catalogs are carried by tutorial prose and have no generated reference yet — recorded honestly, not faked.

## UI and multi-example series acceptance (#57)

The whole UI series (UI01–UI15, parent [#57](https://github.com/CaiZongyuan/axum-saas-template/issues/57)) — all 61 user stories — was accepted on the integrated revision 4f971ed plus this ticket's acceptance repairs (the head commit of the corresponding PR):

- **Gates and journeys**: `just check`, `just check-full` (12 specs, 15 real-browser journeys, including database pause/recovery, a real rate-limit window, two-browser session isolation, Worker crash recovery and a real object-storage failure retry) and `just e2e-docs` (public site zh/en × light/dark × narrow screens and base paths) all pass on this revision. The legacy-fallback contracts — unknown paths fall back to the universal home, and notifications stay readable with understandable unavailable feedback after the target business is removed — are covered by the app-shell and notification contract tests, while the post-deletion/revocation "no longer exists" feedback keeps running inside the e2e journeys.
- **Multi-example combinations**: CI's example-removal job (every PR) drills, on the same revision, the dirty-copy refusal, dual → notes-only → core-only, an independent knowledge-only copy, and a new business joining through the public interfaces; every combination's gate (`check-core`, docs build, typecheck, frontend tests, web build, boundary check) passes. The desktop secure shell is verified by the desktop-smoke job (every PR).
- **Performance budgets**: the only budget-baseline change in the series is UI05 adding the design-system showroom and the icon catalog to the lazy-loading baseline (a tightening); the 400/500 KiB first-load ceilings in `perf-ci` were never raised, and the showroom and icon catalog stay out of the first bundle.
- **Public pages**: Landing, Documentation, Blog and Downloads — both languages, both themes, narrow-screen navigation, base paths, metadata and real CTAs — are covered by `e2e-docs` and the docs contract tests; Blog and Downloads clearly say "coming soon" instead of presenting placeholders as delivered.
- **Tutorials and migration cleanup**: online chapters are bilingual per the published list (`docs:check` enforces registration and consistency); bilingual tutorials, example registration and behavior tests shipped with their implementation tickets, and post-removal bilingual trimming is verified by the example-removal job's docs build. The old-message/old-docs migration items and unwired legacy plumbing are cleared. One gap remains: tutorial 16 (Redis body cache with database fallback) never got its English translation inside the owning ticket's scope; it keeps an honest pending marker and is tracked in [#96](https://github.com/CaiZongyuan/axum-saas-template/issues/96).
- **Acceptance repairs**: the acceptance run exposed 7 early e2e journeys still assuming register/sign-in stays on the old home view and relying on the runner's default language (the UI04 device-language probe renders English). They now pin `zh-CN` following the existing password-reset pattern and assert the actual landing (register/sign-in enter the documents entry; the sign-out control lives on the universal home view). No new abstraction, no weakened assertion.
- **Story 61**: this section is the acceptance record for "integrate the current v1 implementation and acceptance before the next round"; the next UI/site round starts from this revision.
